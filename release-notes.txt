Version 1.6.2

• Fixes the -34018 “A required entitlement is not present” Keychain error introduced in 1.6.1.
• The current public build is still ad-hoc signed, so it cannot use the data-protection Keychain mode that requires application entitlements.
• Restores the traditional macOS Keychain storage path while keeping Touch ID / Mac authentication as the app gate before protected data is loaded.
• Existing stored credentials remain compatible.
• On an ad-hoc-signed build, macOS may ask for Keychain trust again after an app update. Choosing “Always Allow” trusts the currently installed build.
• Keeps the Staff email chevron alignment fix from 1.6.1.
